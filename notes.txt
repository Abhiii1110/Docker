Docker is a tool designed to make it easier to create, deploy, and run applications by using containers.
Think of it like shipping cargo. Before shipping containers, moving goods on ships was messy because boxes, barrels, and sacks all had different shapes. The standard shipping container changed everything because any crane, ship, or truck could handle it. Docker does the exact same thing for software.

📦 Core Concepts You Need to Know

• Containers: A lightweight, standalone, and executable package of software. It includes everything needed to run an application: code, runtime, system tools, system libraries, and settings.
• Images: The blueprint or snapshot used to create a container. Images are read-only templates. If a container is a running house, the image is the blueprint.
• Docker Hub: A cloud-based registry where you can find and share Docker images (like GitHub, but for Docker images).
• Dockerfile: A simple text file containing the sequential instructions and commands needed to build a Docker image.

⚖️ Containers vs. Virtual Machines (VMs)

People often confuse containers with Virtual Machines. Here is how they differ:

Feature	Virtual Machines (VMs)	Docker Containers
Architecture	Includes a full guest Operating System (OS).	Shares the host OS kernel.
Size	Large (usually gigabytes).	Lightweight (usually megabytes).
Startup Time	Slow (minutes to boot the OS).	Fast (seconds or milliseconds).
Efficiency	Higher resource overhead.	Highly resource-efficient.


🚀 Why Developers Use Docker

• "It works on my machine" is solved: Because the container includes all dependencies, it runs exactly the same on your laptop, a testing server, and the cloud.
• Isolation: You can run multiple containers on the same computer without their dependencies crashing into each other (e.g., running one app that needs Python 2 and another that needs Python 3).
• Speed: You can start, stop, or destroy containers in seconds.

🛠️ The Basic Workflow

1. You write a Dockerfile to define your environment.
2. You build this file into a reusable Image.
3. You run that image to spin up a live Container.
